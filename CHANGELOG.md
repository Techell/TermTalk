## 0.6.0 — 2026-10-21

- Меню серверов при старте, F3, ручной IPv4/порт, локальная книга WSS1 до 16
  адресов; F4 /disconnect возвращает в меню, /connect меняет сервер без перезапуска.
- Анонимный STATUS без регистрации, фактическая ёмкость, RTT и вертикально
  отражённые цветные полосы. Connect ограничен сроком, проба отменяется в фоне.
- Серверные --max-clients 1..32 (по умолчанию 10), --max-file-gib 0..1024 либо
  --max-file-bytes. По умолчанию 32 ГиБ на один файл, 0 запрещает передачи.
  Дополнительный слот обслуживает STATUS и отклонение HELLO при полном сервере.
- Файлы через /sendfile, /accept, /reject, /cancel: согласие, блоки 4096 байт,
  ACK/прогресс, SHA-256 CNG, атомарное сохранение без перезаписи, очистка part при
  отмене/разрыве. Размеры и смещения 64-битные; сервер не хранит файлы.
- Модули адресов, пробы и файлов отделены от UI/команд/владельцев сокетов.
  Обновлены русские Doxygen-контракты, документация и карта задач.

### Совместимость и проверка

WSCK v2 несовместим с 0.4/0.5 (v1): обновлять клиент и сервер вместе. Существующие
позиционные аргументы и WSH1 сохранены. Бинарный максимум payload теперь 4108.
Публичные заголовки расширены: настраиваемые конструкторы, u64 кодек, новые модули.
Для до-1.0.0 это MINOR по принятому соглашению SemVer.

Проверки включают 32 участника, статус полного сервера, границу 32 ГиБ,
реальные C-клиенты с бинарными/пустыми/Unicode файлами, отказ/отмену/разрыв,
ошибочный SHA, гонку сохранения, переключение серверов и рестарт книги адресов.
Нативная консоль проверяет меню, русский ник, F4 и повторное подключение.
Полная передача 32 ГиБ не выполнялась; проверены u64 кодек, объявленные пределы
и разреженный источник 32 ГиБ + 1 байт. Подробности: docs/BUILD-VERIFICATION.md.
Группы, файловые элементы меню, возобновление и защищённое соединение остаются
будущими задачами; модель криптографии обсуждается отдельно.

## 0.5.0 — 2026-10-20

### UI-01, UI-02, HIST-01 и HIST-02

- Терминальный экран с собственной палитрой, логотипом, статусом сервера,
  участниками, личной историей, редактором, непрочитанным и клавиатурной навигацией.
- `/help` с описанием команд, F1, F2 и `/lang en|ru`; русский Unicode-ввод и
  UTF-8 сообщения независимо от языка интерфейса. Интерактивная форма никнейма.
- Отдельные библиотеки модели, UI, транспорта, хранилища и контроллера. Один
  сетевой работник с ограниченными очередями; модель/вывод — у основного потока.
- Локальная история до 256 сообщений в `%LOCALAPPDATA%\WinSock\history`,
  `--history-dir`, `--no-history`, `/history on|off|save|clear`. WSH1 проверяется
  целиком, записывается через временный файл и атомарную замену. Повреждение
  отключает автоматическую запись; старый журнал не затирается пустой историей.
- Добавлены проверки очереди событий, Unicode-редактора/раскладки/хранилища,
  настоящего screen buffer, ввода русского ника в запущенный клиент и
  независимые проверки EN/RU, кириллицы, рестарта, отключения/очистки истории.

### Совместимость и переход

- WSCK v1 сохранён: клиент 0.5.0 совместим с сервером 0.4.0. Серверный формат не меняется.
- Прежние позиционные аргументы работают; без nickname в настоящей консоли
  открывается форма, при перенаправлении остаётся Guest-PID. Добавлены флаги
  `--lang en|ru`, `--no-history`, `--history-dir path`, `--help`.
- Публичный `Chat_Run` теперь принимает endpoint, nickname и ChatOptions и
  владеет создаваемыми ресурсами. Старый глобальный API console_ui заменён
  объектным адаптером. Это несовместимое изменение C API до 1.0.0.
- История включена по умолчанию, сохраняется при выходе зарегистрированного
  клиента и по явной команде. Отключение относится к текущему запуску; для
  постоянного запуска без сохранения передавай `--no-history`.
- Журнал содержит открытый текст, не подтверждает личность и доставку;
  авария может потерять несохранённые сообщения. Сложные Unicode-графемы и
  разные терминалы имеют ограничения, перечисленные в docs/UI.md.

## 0.4.0 — 2026-10-20

### PROTO-01, CHAT-01 и CHAT-02

- Реализован WSCK v1: 16-байтовый заголовок, big-endian числа, инкрементальный
  разбор разрезанных/склеенных кадров, строгие размеры, UTF-8 и состояния.
- Добавлены HELLO/WELCOME, LIST_REQUEST/LIST_RESPONSE, CHAT_SEND/CHAT_EVENT/ACCEPTED,
  PING/PONG, GOODBYE и ERROR. Максимальный payload — 4104, текст — 4096 байт.
- Сервер регистрирует уникальные никнеймы и назначает ID, не переиспользуемый до
  перезапуска; рассылает полные списки с никнеймом, IP/портом и статусом online.
- Личное сообщение получает только указанный адресат. Сервер определяет отправителя
  по соединению, проверяет обе очереди до постановки и явно сообщает ошибки.
- Клиент поддерживает /list, /to ID, /msg ID text, /ping и /quit. Простой текст
  отправляется выбранному участнику; после его отключения выбор сбрасывается.
- Явный никнейм читается из Unicode-командной строки Windows и передаётся в UTF-8.
- Регистрация и неполный кадр ограничены абсолютными 10-секундными сроками.
- Сохранены транспортные проверки, добавлены контракт кодека, штатного закрытия
  приложения и независимые Python-проверки обоих направлений протокола.

### Совместимость и переход

- Клиент и сервер нужно обновлять вместе: сырые байты 0.3.0 больше не принимаются.
- Формат запуска: client [IPv4 [port [nickname]]]. По умолчанию `Guest-<PID>`.
- Chat_Run теперь принимает никнейм. Добавлены protocol.h и chat_server.h;
  ServerLoop предоставляет lifecycle-заимствование, отзываемое до повторного слота.
- Резерв payload 65536 из старого проекта спецификации не вводится. Реализованы
  только команды личного чата с собственными пределами; файлы потребуют отдельной задачи.
- ACCEPTED означает серверную очередь, а не получение или прочтение. История,
  постоянные аккаунты, группы, файлы и шифрование ещё не реализованы.

### Проверка

Сборка MinGW GCC 6.3.0 без предупреждений, CTest 8/8, генерация Doxygen 1.18.0.
Проверены десять участников, повторные подключения, приватность при третьем клиенте,
повреждённые кадры/ID, очередь, таймеры, Unicode-никнеймы и обмен реальных C-клиентов.
Подробный отчёт и непроверенные окружения — docs/BUILD-VERIFICATION.md.

## 0.3.0 — 2026-10-20

### NET-02: частичные операции

- Детерминированно проверены короткие send/recv, добавление данных после
  частичного send, WSAEWOULDBLOCK, EOF, ошибки, границы и отсутствие прогресса.
- Отдельная проверка заполняет системные TCP-буферы и подтверждает полное
  восстановление потока после возобновления чтения без потерь и перестановок.
- Подмена системных вызовов доступна только отдельной тестовой сборке.

### NET-03: сервер нескольких клиентов

- Добавлены Server_Listen, Server_Accept и однопоточный ServerLoop с реестром
  до десяти клиентов, ограниченными проходами, select и повторным использованием слотов.
- Сначала обслуживается готовая отправка, затем приём; пустые очереди не входят
  в write-набор. Очередь TX отделена от размера ввода и составляет 64 КиБ.
- Переполнение или 5 секунд без прогресса TX отключают отставшего получателя.
  Остаток после входящего EOF ограничен 3 секундами; остановка освобождает весь реестр.
- ServerLoop имеет callback байтов, не зависящий от UI и будущего кодека.
- Приложение сервера демонстрирует рассылку полученных байтов всем остальным
  TCP-соединениям; Ctrl+C/Ctrl+Break запрашивают остановку у владельца сокетов.

### Несовместимость и переход с 0.2.0

- Server_Initialize удалён. Для независимого обслуживания используйте
  Server_Listen и Server_Accept либо ServerLoop_Create/Poll/Destroy.
- Структура Client содержит TX на NETWORK_TX_CAPACITY (64 КиБ); INPUT_BUF_MAX
  относится к вводу/фрагменту приёма. Потребителям C API требуется пересборка.
- Сервер больше не является консольным собеседником, не читает stdin и не
  завершается при уходе первого клиента. Запускайте два клиента для обмена.
- TCP-байты по-прежнему не имеют кадров или ID. Это не совместимая реализация
  предложенного бинарного протокола, личных или групповых чатов.

### Проверка

Чистая сборка MinGW GCC 6.3.0 с C11 без предупреждений; CTest 6/6:
network_contract, network_partial, network_pressure, server_loop_contract,
chat_smoke, server_smoke. Проверены десять клиентов, превышение лимита, EOF/RST,
повторные подключения, обмен двух собранных C-клиентов через сервер и продолжение работы быстрых при медленном получателе.
Генерация Doxygen проверена для новых публичных заголовков без предупреждений. Границы проверки
описаны в docs/BUILD-VERIFICATION.md; кадров, файлов и шифрования пока нет.

## 0.2.0 — 2026-10-20

### Транспорт NET-01

- Добавлены ClientState, независимый входящий EOF и проверки допустимости операций.
- Добавлены Client_BeginDrain и Client_ShutdownSend для отправки остатка перед
  завершением исходящего направления; приём остаётся разрешён.
- Повторная инициализация живого соединения отклоняется без потери сокета.
- Добавлены NetworkError, NetworkLocalError и диагностическое описание с исходным
  кодом Winsock. Неизвестные системные коды сохраняются.
- Заполнение очереди приложения возвращает SOCKET_QUEUE_FULL без разрыва связи;
  интерфейс сообщает отказ постановки сообщения.
- Добавлена проверка network_contract: состояния, очередь, владение, half-close,
  ответ после завершения отправки и аварийный сброс через loopback.

### Несовместимые изменения C API и переход

- Вместо неинициализированного Client нужен `Client client = CLIENT_INITIALIZER`.
- Поле connected заменено состоянием; читать его через Client_GetState.
- Socket_Recv принимает Client*, а не SOCKET, чтобы учитывать состояние и EOF.
- Переполнение Socket_Send возвращает SOCKET_QUEUE_FULL (-3), а не -1 с WSAENOBUFS.
  Этот результат нужно обработать отдельно, без чтения WSAGetLastError.

Клиент и сервер обновлены вместе с библиотекой. Текстовый формат обмена не менялся.

### Документация и выпуск

- Подключена необязательная цель Doxygen, публичные контракты описаны на русском.
- Главная страница Doxygen выбирается по имени README.md, независимо от длинного
  или короткого Windows-пути к проекту.
- Описаны владение, состояния и ограничения транспорта; обновлена дорожная карта.
- Зафиксированы правила SemVer и аннотированных тегов Git.

### Проверка и ограничения

Сборка MinGW GCC 6.3.0 без предупреждений; CTest: network_contract и chat_smoke.
Генерация HTML Doxygen 1.18.0 проверена; визуальный просмотр страниц не выполнялся.
Сеанс пока использует два потока, connect и первоначальный accept блокирующие.
NET-01 остаётся на совместном ревью. NET-02 (принудительные частичные отправки),
NET-03 (сервер нескольких клиентов), бинарные кадры, группы, файлы и E2EE
не объявляются реализованными. Ручная проверка UI и LAN в этот выпуск не входит.

Предыдущая числовая основа CMake — 0.1.0; отдельного Git-выпуска с этим номером не было.
