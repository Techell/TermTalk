# Работа с проектом TermTalk

- Перед изменением модуля прочитай README и относящиеся к нему разделы docs/ARCHITECTURE.md и docs/PROTOCOL.md. Предложенный протокол не считается уже реализованным.
- Пользователь просит сопровождать код комментариями. Публичные функции и типы документируй в заголовках в стиле Doxygen на русском: назначение, параметры, результаты, предусловия, владение и ограничения.
- В реализации комментируй причины неочевидных решений, синхронизацию и обработку частичных операций. Не повторяй очевидное действие каждой строки; поддерживай комментарий при изменении контракта.
- Правила и пример Doxygen находятся в docs/DOXYGEN.md. Генератор документации необязателен для сборки приложений.
- После изменения поведения обновляй относящиеся проверки, документацию и docs/roadmap.json. Не объявляй готовыми неподтверждённые возможности.
- Старые Client/test.c и Client/test_func.c и их локальные копии удалены по просьбе пользователя; в сборку входят только актуальные приложения и тесты. Не добавляй локальные эксперименты, архивы и производные файлы в Git.
- Выпуски ведём по Semantic Versioning 2.0.0 и docs/VERSIONING.md: версия в CMakeLists.txt, запись в CHANGELOG.md и аннотированный тег vX.Y.Z на проверенном коммите. До 1.0.0 новые возможности и несовместимые изменения повышают MINOR, совместимые исправления — PATCH. Не переносить выпущенные теги. Пользователь поручил выпускать версии; для локального коммита и тега повторное подтверждение не требуется. Отправка в удалённый репозиторий остаётся отдельным действием.
