# Интерфейс и локальная история 0.7.0

## Окно и управление

Клиент использует отдельный Windows screen buffer: исходный экран остаётся
нетронутым и снова активируется при выходе. Собственная тёмная палитра, тёплый
акцент, логотип TermTalk, адрес сервера, статус подключения/регистрации/активного
сеанса и никнейм находятся в шапке. Слева участники с ID и отметками непрочитанного,
справа выбранный личный разговор, внизу уведомление, редактор и горячие клавиши.
Подтверждение `server queue / очередь сервера` не означает доставку.

При ширине менее 78 ячеек список открывается по Tab вместо истории; при ширине
от 78 обе области видны одновременно. Минимум рабочего экрана — 40×18, меньший
размер показывает просьбу увеличить окно. Рендер ограничен 320×160 ячейками.
Раскладка пересчитывается при изменении размера; обычные обновления перезаписывают
только изменившиеся отрезки строк, без регулярной очистки/прокрутки всего экрана.
Длинный текст переносится, длинные слова разделяются по целым Unicode-символам.

| Клавиша | Действие |
|---|---|
| F1, `/help` | Справка с описаниями команд; PgUp/PgDn прокручивают её |
| F2, `/lang en`, `/lang ru` | Язык интерфейса в текущем сеансе |
| Tab | Участники / ввод |
| ↑/↓, Enter в списке | Выделить участника и выбрать личный разговор |
| ←/→, Home/End, Backspace/Delete | Редактировать строку без разрыва UTF-8 |
| Enter, Shift+Enter | Отправить / добавить новую строку |
| PgUp/PgDn | Прокрутить историю текущего разговора |
| Ctrl+R, Ctrl+U | Обновить участников / очистить ввод |
| Esc | Закрыть справку, вернуться к вводу и последним сообщениям |
| Ctrl+Q, Ctrl+C, `/quit` | Штатно завершить сеанс |

`/list`, `/to ID`, `/msg ID текст`, `/ping`, `/quit` совместимы с 0.4.0.
`/help`, `/lang`, `/history` обрабатываются локально и не создают сетевых кадров.
Отсутствие nickname в интерактивном запуске открывает форму входа с F2; пустой,
слишком длинный или содержащий управляющие символы никнейм не принимается.
При переданном nickname форма пропускается. При перенаправлении stdin форма
не потребляет команды: используется `Guest-<PID>`, если ник не указан.

Ввод использует `ReadConsoleInputW` и Unicode-события, вывод — `WriteConsoleOutputW`.
Кодовые страницы процесса не переключаются. Поддержаны русские/английские буквы,
скаляры вне BMP переводятся в пары UTF-16. Геометрия emoji, CJK, combining marks
и сложных графем зависит от терминала/шрифта; редактор работает по скалярам,
а не по графемным кластерам. Ручная проверка всех терминалов Windows не выполнена.

При перенаправлении любого стандартного потока используется обычный UTF-8 вывод
без цветов/курсорных команд. Частичная входная строка не блокирует сетевые события.
Некорректный NUL или превышение ёмкости строки завершает сеанс с ошибкой;
ошибочная команда/текст получает объяснение. Интерфейс EN/RU не ограничивает
язык никнеймов и сообщений. Текст пользователя выводится как ячейки, а не ANSI-код.

## Решение HIST-01 и реализация HIST-02

Пользователь выбрал историю на локальном диске с отключением сохранения.
Отдельный модуль `history_store` не зависит от консоли, не хранит сокеты и не
вызывает сетевые операции. Ограничение — 256 последних сообщений суммарно по
всем разговорам, включая исходящие. Старейшие вытесняются; это не бессрочный архив.
Время — локальные часы клиента, не подтверждённое сервером время доставки.

Область профиля — точная строка `IPv4:порт` и точные UTF-8 байты вашего никнейма.
Имя файла вычислено из хешей; сырые пользовательские строки не используются
как пути. Заголовок также содержит полную область профиля и проверяется при
чтении. Каталог по умолчанию `%LOCALAPPDATA%\WinSock\history`, переопределение
`--history-dir path`. Каталог создаётся только при сохранении.

Собеседники в сохранённой истории связываются по точному никнейму; сетевые ID и
request ID не сохраняются. После перезапуска сервера и смены ID прежний разговор
остаётся доступным при выборе того же ника. Ник не аутентифицирован: другой
человек может занять то же имя. Результат прежней отправки после загрузки
помечается «из журнала», без заявления о доставке. Если ник отправителя неизвестен,
сохраняется `#ID`, автоматически отождествлять его с новым человеком нельзя.
При отсутствии выбранного участника видна общая локальная лента с адресатами.

### Управление записью

- По умолчанию журнал читается при входе; записывается при завершении
  зарегистрированного сеанса и по `/history save`. Авария процесса/выключение
  могут потерять изменения после последнего сохранения.
- `--no-history` пропускает чтение и автоматическую запись и не создаёт каталог.
  Это способ запускать приложение без сохранения каждый раз.
- `/history off` отключает запись до конца текущего сеанса, не стирает уже
  записанное и не удаляет историю из памяти.
- `/history on` разрешает сохранять текущую модель; не подмешивает старый файл
  поверх текущего разговора. `/history save` требует включённого сохранения.
- `/history clear` явно удаляет только файл текущего профиля и очищает память.
  При включённом сохранении последующие сообщения начнут новый журнал.
- Ошибка чтения/повреждение отключает автоматическое сохранение, чтобы не
  перезаписать прежний журнал пустыми данными. Ошибка записи показывается;
  старый файл не открывается на усечение. Переписка через сеть продолжается.
  Ошибка финальной записи также выводится в исходный stderr после восстановления
  экрана, чтобы она не исчезла вместе с полноэкранным интерфейсом.

Файл — открытый локальный текст в бинарном контейнере, доступный с правами
пользователя Windows. Контрольная сумма обнаруживает повреждение, но не защищает
от намеренной подмены. Шифрование файла, аутентификация, синхронизация между
устройствами и координация одновременных писателей в один профиль не реализованы.
Все команды переключения относятся к текущему запуску; постоянных настроек пока нет.

### Формат WSH1

Все целые беззнаковые, big-endian. Файл не больше 1 100 000 байт, каждая строка
проверяется по тем же ограничениям UTF-8, что сетевой текст/никнейм.

| Поле | Размер |
|---|---|
| Magic `WSH1` | 4 |
| Длина endpoint, длина своего ника, число записей | 2 + 2 + 2 |
| Резерв, строго ноль | 2 |
| endpoint и свой ник, UTF-8 без NUL | По длинам |
| Записи по порядку | По числу записей, до 256 |
| FNV-1a 32 всех предшествующих байтов | 4 |

Запись: направление u8 (0 входящее / 1 исходящее), резерв u8=0, длина ника u16,
длина текста u32, Unix timestamp u64 (до 2100-01-01), затем ник и текст без NUL.
Ник 1..32 байта, текст 1..4096. Хвостовые байты, неверные размеры, резерв,
контрольная сумма и несовпадающий профиль отклоняются. Сначала проверяется весь
файл во временной ограниченной памяти, затем одним действием заменяется история.

Запись идёт во временный файл того же каталога с PID, затем `FlushFileBuffers`,
закрытие и `MoveFileExW(REPLACE_EXISTING | WRITE_THROUGH)`. Неудачная запись не
уничтожает прежний файл. Один профиль рассчитан на один работающий клиент;
сложный журнал транзакций и блокировки между процессами остаются развитием модуля.

## Серверы и файлы 0.6.0

При старте без IP открывается меню стандартного/сохранённых серверов; адрес
можно ввести как IPv4:port или IPv4 port, без порта используется 5050. F3 открывает
это меню во время разговора, ↑/↓ выбирают адрес и очищают строку ручного адреса,
Enter подключает, F5 проверяет, Esc возвращает. Черновик разговора хранится отдельно.
F4 или /disconnect завершает соединение и открывает меню заново; /connect задаёт
другой адрес напрямую. Никнейм остаётся, история разделяется по серверу и нику.

Проба ждёт паузу набора 350 мс, работает в фоне до 1,5 с и отменяется при смене
адреса. Ответ WSCK показывает online, число участников/ёмкость и RTT. Ошибка
соединения означает «нет ответа/недоступен», не доказывает выключение компьютера.
Автоопрос раз в 3 с, в активном сеансе PING/PONG. Полосы отражены вертикально,
верхний край общий: █▀▔ зелёный <=100 мс, ▀▔ жёлтый <=250 мс, ▔ красный иначе
или при 5 с без ответа. До первого измерения показано ожидание, без ложного 0 мс.

WSS1 хранится в LOCALAPPDATA/WinSock/servers.wss, --history-dir меняет каталог.
Сохраняются до 16 успешных адресов без дублей, стандартный адрес закреплён первым.
--no-history отключает загрузку и автоматическую запись книги; /history off
приостанавливает её автоматическую запись. Статусы не записываются на диск.

/sendfile ID путь, /accept TRANSFER путь, /reject TRANSFER, /cancel — первый
командный интерфейс отдельного модуля FileTransfer. Путь с пробелами можно
заключить в кавычки. Приём требует явного нового пути, существующий файл остаётся.
В строке прогресса отображаются подтверждённые байты отправки/записанные байты
приёма и итоговое состояние. /status сообщает предел сервера в байтах; по умолчанию
32 ГиБ на один файл. Выбор файлов/папок реализован в 0.7.0, описание ниже. Список нескольких
передач и возобновление не реализованы.

## Подсказки команд и файловая панель 0.7.0

Каталог CommandHint содержит 16 команд с EN/RU описаниями. При вводе первого
токена `/…` список размещается строго под строкой редактора; история/уведомление
сдвигаются выше. До пяти подсказок, в минимальном окне 40×18 две; выделение
прокручивает список. ↑/↓ меняют выбранную команду, Tab вставляет имя и пробел
при наличии аргументов, Enter выполняет введённую строку. Esc скрывает список
до следующего изменения строки. В аргументах и обычном тексте Tab по-прежнему
переключает участников. Подсказки не работают в форме ника, меню и справке.

F6 или /sendfile [ID] открывает отдельную однопанельную файловую область. Нет
второй панели и системного окна Explorer: путь, список и управление нарисованы
тем же Windows console адаптером. Отдельный черновик хранит текст разговора.
↑/↓, PgUp/PgDn выбирают записи; Enter открывает каталог/отправляет файл,
Backspace при пустом поле и строка .. ведут наверх, F6 показывает диски,
F5 обновляет, Ctrl+L редактирует текущий путь, Esc возвращает. Нижнее поле
принимает полный путь, включая внешние кавычки. На 512 записях снимок усечён
с явным уведомлением; полный путь остаётся доступным.

/accept без ID относится к единственному текущему предложению. Первый экран
предлагает downloads в каталоге исполняемого клиента (создаётся после Enter)
либо выбор другого каталога. Во втором случае Enter открывает папку, F7
подтверждает текущую. Имена очищаются от недопустимых Windows-символов/device
names; существующему имени подбирается суффикс. Если файл появился после
подбора, FileTransfer откажет, а не перезапишет его. Явные старые команды
/accept TRANSFER путь и /reject TRANSFER поддержаны; /reject без аргументов
отклоняет текущее предложение. Esc закрывает выбор, сохраняя само предложение.
Его завершение по таймеру/отмене/разрыву закрывает диалог и сообщает причину.

Работник каталога не рисует и не удерживает указателей в модель. Модель получает
готовую копию снимка; входящие сообщения и передача продолжают обрабатываться.
Режим ошибок работника подавляет системные окна пустых съёмных дисков, возвращая
ошибку в панель. Отмена кооперативная, между WinAPI-вызовами; зависшая файловая
система может задержать выход приложения при ожидании работника.

## История команд 0.8.0

В активном разговоре ↑ вызывает предыдущую slash-команду, ↓ — более новую.
После последней записи возвращаются исходный черновик и положение курсора.
Лимит — 20, самые старые вытесняются; точный повтор подряд не добавляется.
Запоминаются попытки ввода команд, включая команды с ошибкой; обычные сообщения
не входят. Enter выполняет выбранную/отредактированную команду, сама навигация
ничего не отправляет. Ctrl+U сбрасывает навигацию. При видимых подсказках ↑/↓
выбирают подсказку, Esc скрывает её; в остальных панелях работают их клавиши.
История только в RAM текущего подключения, не зависит от /history и очищается
перед следующим подключением. Это не защищённое стирание памяти процесса.

## TermTalk: никнейм перед подключением

В отключённом меню серверов нажмите F7, чтобы открыть форму никнейма.
Текущее имя подставлено в редактор; Ctrl+U очищает его, Enter сохраняет,
Esc отменяет при наличии прежнего имени. Допустимо 1..32 UTF-8 байта без
управляющих символов. Адрес, курсор адреса и выбранный сервер сохраняются.
После отказа из-за занятого имени меню остаётся открытым: F7 → новое имя →
Enter → Enter для повторного подключения. После первого F7 при запуске
повторная форма никнейма не появляется. Во время активного соединения F7
не переименовывает участника: сначала F4, затем F7 в меню.

Имя и логотип приложения изменены на TermTalk. Пути LOCALAPPDATA/WinSock
и формат WSCK v2 сохранены для совместимости с существующими данными.
