# Doxygen: комментарии как документация API

## 1. Что делает инструмент

Doxygen читает исходные файлы и специальные комментарии, затем создаёт справочник: типы, поля структур, параметры функций, результаты и перекрёстные ссылки. В нашем проекте он объединяет описание публичного C API с существующими Markdown-документами.

Комментарии рядом с объявлениями объясняют локальный контракт; ARCHITECTURE объясняет устройство системы и причины решений. Эти документы дополняют друг друга. Doxygen не выполняет функции, не доказывает соблюдение контракта и не заменяет тесты.

Инструмент относится к разработке, а не к библиотекам приложения. Собранный клиент не требует Doxygen, Python или Graphviz для запуска.

## 2. Как подключено к CMake

В корневом CMakeLists.txt добавлена опция:

```cmake
option(WINSOCK_BUILD_DOCS "Enable the Doxygen documentation target" OFF)
```

При включении CMake ищет программу через `find_package(Doxygen REQUIRED)`, задаёт параметры и вызывает `doxygen_add_docs(docs ...)`. Модуль CMake сам создаёт Doxyfile для выбранной папки сборки. Не нужно вручную поддерживать ещё одну копию тех же настроек. Описание механизма: [FindDoxygen](https://cmake.org/cmake/help/v3.16/module/FindDoxygen.html).

Цель `docs` запускается явно и не входит в обычную сборку. Выход — HTML, язык интерфейса русский, входные файлы UTF-8. LaTeX и обязательная зависимость от Graphviz не включены. Заголовки и Markdown перечислены явно: пользовательские эксперименты и каталоги сборки не сканируются как API.

Для справочника извлекаются документированные сущности публичных заголовков. Внутренние функции `.c` не включены в этот набор входов; их обычные комментарии всё равно нужны при чтении реализации. Генерация выдаёт предупреждения об ошибках документирования. Пока предупреждения документации не превращаются автоматически в ошибку сборки.

## 3. Установка в Windows

На 2026-10-15 генерация проверена с Doxygen 1.18.0, установленным в `C:/Program Files/doxygen/bin/doxygen.exe`. Если инструмент ещё не установлен, используй Windows-версию с [официальной страницы загрузки](https://www.doxygen.nl/download.html). Конкретная версия не зафиксирована проектом.

Добавь папку с `doxygen.exe` в пользовательский PATH и открой новый терминал. Проверка:

```powershell
doxygen --version
```

Если PATH не используется, при конфигурации можно явно передать путь к программе через `-DDOXYGEN_EXECUTABLE="C:/путь/к/doxygen.exe"`. Это путь установленного инструмента; исходники переносить не требуется.

## 4. Генерация

Из корня проекта в PowerShell:

```powershell
$fso = New-Object -ComObject Scripting.FileSystemObject
$projectPath = $fso.GetFolder((Get-Location).Path).ShortPath
cmake -S $projectPath -B "$projectPath\build" -G "MinGW Makefiles" -DWINSOCK_BUILD_DOCS=ON
cmake --build "$projectPath\build" --target docs
```

Справочник создаётся внутри общей папки `build/docs`, приложения и тесты остаются в `build`. Короткий путь нужен установленному старому MinGW Make, как и для сборки приложений. Выполняй вторую команду после успешной конфигурации.

Если проект перенесён или переименована родительская папка, кэш может содержать прежний абсолютный путь. Ошибки `CMakeCache.txt directory ... is different` и `source directory ... does not appear to contain CMakeLists.txt` возникают до запуска Doxygen. Заново вычисли текущий путь и пересоздай настройки (команда `--fresh` требует CMake 3.24+):

```powershell
$fso = New-Object -ComObject Scripting.FileSystemObject
$projectPath = $fso.GetFolder((Get-Location).Path).ShortPath
cmake --fresh -S $projectPath -B "$projectPath\build" -G "MinGW Makefiles" -DWINSOCK_BUILD_DOCS=ON
cmake --build "$projectPath\build" --target docs
```

`--fresh` пересоздаёт `CMakeCache.txt` и служебный каталог `CMakeFiles`; дополнительные параметры прежней конфигурации нужно передать снова. Для CMake 3.16–3.23 используй новую папку сборки, например `build-new`, в обеих командах вместо `build`, без `--fresh`. Не исправляй старые пути вручную: они записаны также в сгенерированных файлах сборки.

Открой результат в браузере:

```powershell
Start-Process .\build\docs\html\index.html
```

При изменении комментариев повтори команду сборки цели `docs`. При добавлении заголовков или страниц включи их в список `doxygen_add_docs` и повтори конфигурацию. Сгенерированные файлы находятся в игнорируемой Git папке сборки; в репозитории храним исходники, комментарии и настройки.

Mermaid-диаграммы сохраняются в исходных Markdown. Их отображение внутри Doxygen зависит от возможностей используемой версии; данная конфигурация не добавляет отдельный обработчик Mermaid и не гарантирует их отрисовку.

## 5. Как писать комментарий

Обычный `/* ... */` помогает читающему реализацию. Блок `/** ... */` — документирующий комментарий. Ставим его перед объявлением функции в заголовке, чтобы контракт был доступен её пользователю. Синтаксис описан в [руководстве Doxygen](https://www.doxygen.nl/manual/docblocks.html).

Пример из нашего API в сокращённом виде:

```c
/**
 * @brief Проверить десятичную запись порта.
 * @param[in] text NUL-терминированная строка цифр.
 * @param[out] port Получает результат только при успехе.
 * @retval 0 Значение находится в диапазоне 1..65535.
 * @retval -1 Ввод неверен; прежнее значение port не меняется.
 */
int Parse_Port(const char *text, u_short *port);
```

`@brief` даёт краткое назначение; `@param` объясняет аргумент. `[in]` означает чтение данных, `[out]` — запись результата, `[in,out]` — чтение и изменение. Это документация, а не проверка компилятора. Для выходного указателя нужно отдельно определить, что происходит при ошибке.

`@retval` описывает конкретный результат, `@return` — более общее правило результата. `@pre` фиксирует предусловие, `@note` — существенное замечание, `@warning` — ограничение, нарушение которого может привести к ошибке. `@invariant` описывает сохраняемое условие структуры. После поля удобно использовать `/**< ... */`.

В частности, при работе с указателем документируем доступный размер памяти, время жизни данных, копирование или заимствование. При работе с ресурсом — кто закрывает его. При работе с несколькими потоками — кто меняет объект и какая синхронизация требуется.

Комментарий `/* увеличиваем счётчик */` перед `++count` мало помогает. Комментарий «не включаем пустые очереди в write-набор, иначе select постоянно возвращает готовность» объясняет причину решения и помогает сохранить поведение при рефакторинге.
